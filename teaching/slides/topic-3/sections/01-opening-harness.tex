\subsection{Harness}

% Page 10
\begin{frame}{The Orchestrator--Generator--Critic Design}
\begin{center}
\resizebox{.94\textwidth}{!}{\input{figures/oh_three_roles}}
\end{center}
\begin{itemize}
\item The main session coordinates the work; controller code checks each state transition.
\item Neither the Generator nor the Critic may expand its permissions or bypass a check.
\end{itemize}
\end{frame}

% Page 11
\begin{frame}{Three Roles: Why Separate Them?}
\begin{center}
\small
\input{tables/oh_separation}
\end{center}
\begin{itemize}
\item Separate contexts help the Critic question the proposal, but both agents may make the same mistake.
\item Use the roles when delegation and independent checking add value.
\end{itemize}
\begin{center}\scriptsize
\href{https://www.anthropic.com/research/building-effective-agents}{Source: Anthropic, orchestrator/workers and evaluator/optimizer patterns}
\end{center}
\end{frame}

% Page 12
\begin{frame}{Role Contracts and Authority}
\begin{center}
\small
\input{tables/oh_role_contracts}
\end{center}
\begin{itemize}
\item Roles receive different instructions, context, tools and write permissions.
\item State permissions in the prompt and enforce them through the host or controller.
\end{itemize}
\end{frame}

% Page 13
\begin{frame}{Inside Each Role's Harness}
\begin{center}
\resizebox{.91\textwidth}{!}{\input{figures/agent_harness}}
\end{center}
\begin{itemize}
\item The harness supplies context, tools, saved state and checks on what the role returns.
\item Role prompts describe responsibilities; the surrounding system enforces the boundaries.
\end{itemize}
\end{frame}

% Page 14
\begin{frame}{Task and Artifact Contracts}
\begin{center}
\small
\input{tables/oh_task_contract}
\end{center}
\begin{itemize}
\item Specify the completion and failure conditions before the work begins.
\item Link every returned artifact to its request and supporting evidence.
\end{itemize}
\end{frame}

% Page 15
\begin{frame}{Permissions and Untrusted Inputs}
\begin{center}
\resizebox{.90\textwidth}{!}{\input{figures/untrusted_document}}

\begin{center}
\small
\input{tables/action_mandate}

\begin{itemize}
\item Filings and web pages cannot change permissions. Enforce file and network restrictions through the host.
\item Example: an agent requests paid data. AP2 illustrates signed authorization; QT has no payment access.
\end{itemize}

% Page 16
\begin{frame}{Hooks, Gates and Validation}
\begin{center}
\resizebox{.94\textwidth}{!}{\input{figures/hook_concept}}
\end{center}
\begin{itemize}
\item A hook runs a script when a specified event occurs; the agent need not remember to log it.
\item Observation hooks record events. Blocking hooks stop actions only where the host supports it.
\item Controller gates decide whether the candidate can advance.
\end{itemize}
\end{frame}
