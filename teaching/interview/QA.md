让AI会写代码，更让金融学生会提问题
——张虎来教授课程：《金融人工智能编程》
采访提纲

快问快答

1. 用三个词形容《金融人工智能编程》这门课。

答：提问、协作、核验。

2. 对零基础选课同学说一句话。

答：不必先会写代码，先把想解决的问题说清楚，再学会检查 AI 做得对不对。

3. AI时代，您最希望学生记住的一句话是什么？

答：AI 可以执行任务，但你要对问题、证据和最终判断负责。

正式采访

1.	您能向我们简单介绍一下《金融人工智能编程》这门课吗？

答：这门课教学生用编程智能体完成金融工作，并把这些工作组织成可重复运行的流程。课程先从环境搭建、公司简报等小任务入手，再学习提示词、技能和知识库，最后设计有任务分工、质量检查和故障恢复机制的长程工作流。学生逐步从 AI 的使用者，成为能够组织智能体团队、提供金融分析服务的人。

2.	为什么现在要开这样一门课？AI目前在金融行业已经用在了哪些地方？

答：现在的 AI 已能调用工具、编写和运行代码，参与多步骤的金融工作。比如，[Rogo](https://rogo.com/) 提供金融智能体工作流，[Funda](https://funda.ai/) 将股票研究、数据和持续跟踪结合起来，应用涉及资料整理、公司分析、财务建模和报告生产。开这门课，是希望学生能把自己的金融知识转化为可以执行、检查和持续改进的业务流程。

3.	【课程理念】《金融人工智能编程》的核心词是“短程与长程工作流设计、系统编排、质量校验、专业表达”。您认为这门课和普通的编程课有什么不同？

答：我们围绕完整的金融任务组织教学。学生要明确服务谁、解决什么问题、使用哪些数据，以及怎样判断任务完成。短程工作流练习把一次任务做好；长程工作流进一步处理分工、交接、中断恢复和持续更新。代码是完成任务的工具，金融判断、结果核验和专业表达同样需要训练。

4.	【课堂拆解1】第一讲是“环境搭建与小型交互式金融任务”，大纲提到市场快评、收益与风险指标解读、公司要点摘要等。您能不能分享一个课堂演示：零基础学生第一周面对什么任务、用什么工具、最后交出什么？从第一讲到第三讲，您认为学生最难跨过的是哪一级台阶？

答：第一部分的上机练习是比较苹果、微软等公司的规模、增长和利润率。学生写任务说明，让 Kimi Code 编写 Python 脚本，从 SEC 的公开披露接口取数，再抽取数值与年报核对。最后交付一页 PDF 简报、对比表、任务文档和 Git 提交记录。

我认为最难的一步，是从自己盯着 AI 做完一次任务，转向事先设计好分工、检查和异常处理，让整个流程能够持续运行。

5.	【课堂拆解2】 第二讲同时覆盖买方场景的投资筛选、组合比较、风险收益分析，和卖方场景的业绩点评、公司简报、可比公司分析等。您能不能举一个课堂案例或学生作业：学生面对什么金融问题、用了什么数据和方法、最后得出什么结果？您认为学生最容易踩的坑是什么？

答：第二部分的综合练习是比较五家科技公司的收入、增长和净利率。学生获取年度财务数据，用 Python 计算指标，独立手算抽检，再生成图表、网页和两页报告。课件使用的快照中，微软 FY2026 净利率约为 40.3%，苹果 FY2025 约为 26.9%。这反映各自报告期的盈利表现，财年和业务结构不同，不能直接据此判断哪只股票更值得买。

最需要警惕的是口径错误：混用财年、弄错单位，或把缺失值填成零。图表再漂亮，也弥补不了这些错误。

6.	【课堂拆解3】第三讲专门讲长程工作流的任务分工、流程编排、检查点设置、过程留痕、质量评估、问题修复和持续优化。AI模型有“幻觉”，金融场景又要求严谨，您如何让学生判断“AI跑出来的结果”是否可信？有没有学生踩坑的案例？这算不算这门课里的“模型风险”训练？

答：我要求学生把结论追溯到原始证据，独立复算关键数值，并在流程中设置检查关卡；检查不通过，就不能进入下一步。多个智能体意见一致，也不能代替证据。

课件有一个教学案例：回测错误地安排在收盘信号刚形成时成交；修改后，交易时间通过了检查，却引用了一份不存在的证据。因此两个版本都不能采用。这个练习让学生检查修复是否引入新问题。这属于模型风险训练，也涉及数据和流程风险；通过研究检查，并不等于获得真实交易授权。

7.	期末项目占60%，要求提交GitHub仓库，项目要来自学生自身工作或学习场景，还要写清项目目标、关键工作流步骤、质量检查、项目局限，以及AI在最终成果中的具体作用；仓库里还要有README和提交记录。为什么用这样的形式，而不是传统报告或考试？提交记录能看出什么？您评价一个项目，更看重金融判断、工作流设计、质量校验，还是AI使用的透明度？

答：我把期末项目看作让学生建立自己的“AI 原生公司”：学生担任负责人，由不同智能体承担数据收集、分析、报告撰写和审查等工作，为一个真实需求提供产品。可以参考 Rogo、Funda 在金融领域的产品思路，也可以借鉴法律领域的 [Harvey](https://www.harvey.ai/)，从一个具体业务做起。

因此，项目需要展示整套业务怎样运作：如何分工、怎样验收、出了问题如何恢复，以及如何持续改进。项目文件、README 和完整 Git 历史使这些过程可以被检查。提交记录能帮助追踪问题如何发现、为什么修改、修复是否经过验证；提交次数本身不能证明贡献。

评价时，我会把金融判断、工作流设计、质量校验和 AI 使用透明度放在一起看，判断这套系统能否解决真实问题并可靠交付。学生还必须说清楚自己作了哪些决策、AI 完成了哪些工作，以及系统的局限。

8.	这门课课堂讨论和提问占40%，比很多编程课都高，这样设置的原因是什么？学生没有编程先修要求，您觉得金融背景、理工背景、文科背景的同学，在课堂里各自能贡献些什么？AI降低编程门槛之后，金融专业判断是不是反而更重要？学完这门课，您最希望学生带走哪一项能力？

答：提问和讨论本身就是这门课要训练的能力。能否发现任务定义不清、质疑一个假设、指出证据不足，都需要在交流中体现，所以课堂参与占 40%。金融背景的同学可以贡献业务判断，理工背景的同学可以贡献建模和系统思维，文科背景的同学可以贡献问题分析与表达能力，这些能力也可以相互学习。

代码生成更容易之后，选什么问题、用什么假设、接受什么结论，就更需要专业判断。我最希望学生能把真实需求变成一套由智能体协作完成、自己能够验收的工作流程。
