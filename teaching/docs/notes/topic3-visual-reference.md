# Topic 3 visual grammar

The opening states the product and acceptance in plain language, then derives
controls from stakeholder needs. Explanations use short itemized lists; four
tables retain worked data, calculation, and output comparisons. Diagrams explain
the Orchestrator–Generator–Critic architecture. Solid boxes identify leads; dashed
boxes identify specialists. The final architecture separates production and
review teams, routes evidence through the Orchestrator, and returns a structured
repair packet. Context, tools, gates and persistent state form each role harness.

A separate evolution diagram shows completed cases, diagnosis, a bounded prompt
proposal, fixed evaluation, a decision, versioned adoption and rollback. The
implemented scope is one Generator-prompt change; approval precedes adoption.

The English and Chinese decks use equivalent figures. Personal research-system
names, paths and implementation details are excluded from student materials.

Self-improvement tools are tied to one timing omission. The toolchain sends a
proposed candidate through evaluation before approval/versioning. The manually
written output fixtures on pages 49 and 52 illustrate a repaired timing check
and a failed evidence-reference check; they are not model-performance results.
